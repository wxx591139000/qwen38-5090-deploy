## 四、专业压测结论（思考成本，权威数据）
- **开思考 vs 关思考（同卡 clone2 完整响应，max 放开到 20000 拿到完整 ON）**：
  | | 关思考 | 开思考(完整) |
  |---|---|---|
  | 短任务 wall | 6.5s | 168.9s（**~26×**） |
  | 短任务 token | 297 | 12609（**~42×**，98% 思考） |
  | 长任务 wall | ~40s | >6000 思考仍截断 |
- **思考无边界**：结构化/生成任务想 12600 token 才出正文；`--reasoning-budget` 只对 chat 生效、对 responses 无效。
- **预算甜区**：`--reasoning-budget 500`（16s/320思考，平衡）；1200=27.5s，2500=42s。
- 完整文档在 `docs/benchmarks/`（2026-08-23-single-stream / -concurrency / DFLASH2_research）+ PROGRESS。

## 五、关键坑（必须知）
1. **codex 与服务器思考互斥（根因）**：codex 走 `/v1/responses`；服务器 `--reasoning on` 时 responses 端点触发无限思考（budget 对它无效）→ 空响应/超时 → codex "Reconnecting/high demand"。**codex 可用的机必须 `--reasoning off`**；codex CLI 强制 high effort 无法关。
2. **Hermes `hermes-switch` 两个 bug（已修）**：只改 provider 不改 model.default → 发错模型名；`.Replace` 全量匹配 → clobber tts/stt/memory 的 provider。已改：安全锚定 model 块 + 每目标带 default。
3. **Hermes `-p` 要的是 profile 不是 provider**：`qwenthink` 需建 `profiles/qwenthink/` 独立 profile。
4. **压测脚本对思考流不兼容**：`bench_qwen_production.py` 只统计 `delta.content`，思考开时崩 → 需非流式+`usage`+tokenize(其实现无 /v1/tokenize)。
